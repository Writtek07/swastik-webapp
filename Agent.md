# Working notes for agents

Rails 8 + Tailwind CSS v4 + Stimulus. No database-backed content models for the
marketing pages — everything renders from `Catalog`.

## Where things live

- **Content**: [app/models/catalog.rb](app/models/catalog.rb). Products, nav,
  stats, values, process, clients, FAQs. Add a product here and it appears in the
  navbar mega menu, the catalogue, the footer and the enquiry form's product
  select automatically.
- **Design tokens and component classes**:
  [app/assets/stylesheets/site.css](app/assets/stylesheets/site.css), imported
  from `application.tailwind.css`. Tailwind v4 processes the `@apply` rules, so
  the file must stay in the Tailwind entrypoint's import graph.
- **Product artwork**: `app/views/shared/visuals/_<visual>.html.erb`, selected by
  the `visual` key on a product. Add a new partial and reference it by name.
- **Icons**: `IconsHelper::ICONS` in
  [app/helpers/icons_helper.rb](app/helpers/icons_helper.rb). Call
  `icon(:name, class: "...")`. Unknown names render nothing rather than raising.

## Conventions

- Views use `shared/_page_hero`, `shared/_section_heading`, `shared/_product_card`,
  `shared/_product_media`, `shared/_stats`, `shared/_cta` and
  `shared/_enquiry_form`. Prefer these over new markup so spacing and typography
  stay consistent.
- Every page wraps its content in `<div data-controller="reveal">` and marks
  animatable blocks with `data-reveal-target="item"`. Counters use
  `data-counter` plus `data-suffix`.
- Stimulus controllers must be registered in
  `app/javascript/controllers/index.js`.
- A controller's targets must live inside the element carrying
  `data-controller`. The navbar controller wraps the header, scrim and drawer in
  a `display: contents` div for this reason; the video modal controller sits on
  `<body>` so triggers anywhere on the page can reach it.
- The mega-menu panel is a **sibling** of its trigger group, not a child — it has
  to be, because it spans the full header width. So the hover-close is bound to
  the whole `<header>` (`mouseleave->site-nav#scheduleClose`) rather than to the
  group, and each panel carries `mouseenter->site-nav#keepOpen`. Binding
  `mouseleave` to the group instead makes the panel close the moment the pointer
  travels from the trigger down into it, which breaks clicking any link inside.

- Admin roles rank `staff < owner < super_user` (the enum's integer value is the
  rank). Admin pages are open to every role by default; narrow one with
  `require_role :owner` (optionally `only:`) in the controller, and hide its
  links with `admin_can?(:controller, :action)`, which reads those same
  `require_role` rules — don't repeat role names in views. Inactive admins can't sign in. The staff
  roster uses `Admin.visible_to(current_admin)`: nobody sees admins above their rank.
- Gauge prices (identifiers keep the `guage` spelling; UI copy says "Gauge"):
  a `GuageSession` is a date range of up to a year opened by an owner+, and
  sessions can't overlap (validated, plus a Postgres exclusion constraint).
  `GuagePrice` is unique per session/product/size and can only be written while
  its session is in progress. Only products with `has_guage_price` appear on
  the sheet, one row per entry in `product.sizes`.

- SEO: see [docs/seo.md](docs/seo.md). Every public view sets
  `content_for :title, page_title("…")` and `content_for :description`; the
  layout's `shared/_seo_meta` builds canonical, Open Graph and the JSON-LD graph
  (`SeoHelper`). Add page-specific schema with `structured_data(...)`. Company
  contact details and `SITE_URL` come from ENV (defaults in `Catalog`).
  `robots.txt`, `sitemap.xml` and `llms.txt` are rendered by `SeoController`, so
  there is no `public/robots.txt`. New public pages go in
  `SeoController::STATIC_PAGES`.
- Analytics: see [docs/analytics.md](docs/analytics.md). GA4 events go through
  `app/javascript/lib/analytics.js` (delegated listeners, `gtag('event')`).
  Server-confirmed outcomes use `track_event` in controllers (flash-queued,
  sent once on the next page); page-level ones use `analytics_event` in views.
  Don't add a `page_view` on `turbo:load`: GA4's history-change tracking already
  sends one. Never send personal data.
- Logo: render it with `brand_lockup` (`on: :dark` on always-dark surfaces)
  or `brand_mark`; never hand-place the image files. All logo-derived assets
  (favicons, icons, share image) are regenerated by `script/brand/build`.

## Tailwind v4 gotchas

- `@apply` only accepts real utilities. It cannot reference another custom class
  (`.btn`), the `group` marker, or a hand-written class like `.hatch`. Share
  styles by listing selectors together instead.
- `dark:` is bound to the `.dark` class via `@custom-variant`, not to
  `prefers-color-scheme`.
- Component classes in `site.css` live inside `@layer components`, so a utility
  on the element (`btn-outline text-white`, `btn-primary hidden sm:inline-flex`)
  overrides the component default. Keep new component rules inside that layer:
  unlayered CSS beats every utility and makes those overrides silently fail.
- `icon` gives class-less icons their default 20px size as SVG attributes, not
  `h-5 w-5`, so contextual rules like `.btn-primary svg` can still resize them.
